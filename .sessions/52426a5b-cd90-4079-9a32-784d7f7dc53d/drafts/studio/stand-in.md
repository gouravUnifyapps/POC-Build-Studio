## Schema (what objects.schema means, so the builder has no second question)

- `psl_poc`: add `slack_channel_id`, `owner_slack_id`, `manager_slack_id`, `build_run_id` (the cloud session URL), `slack_live` (boolean), `slack_last_ts`, `bot_thread_ts` (cleared when the manager is noted). `slack_channel` holds the bare channel name; the UI prefixes "#" when it prints it.
- `psl_activity`: add `actor_avatar_url`, `slack_ts`, `slack_ref`. Slack text rows use `input_added` or `document_saved`.
- `psl_feedback`: add `iteration` (optional integer, the loop's number within its POC), the request's "POC name, iteration, stage, feedback text". The one change on top of data-plan.md; seed patch below.
- `psl_skill`: `skill_id`, `name`, `current_version`, `prompt`. Nothing else.
- `psl_skill_suggestion`: `suggestion_id`, `skill`, `from_version`, `to_version`, `summary`, `proposed_prompt`, `evidence_count`, `evidence_tickets`, `status` (`pending`, `approved` only; the data-plan's `rejected` is dropped, no beat or button uses it), `created_at`, `approved_by`, `approved_at`.
- `psl_document`, `psl_iteration`: as data-plan.md.

## The 8 automations and 2 agents (inside the budget, so nothing else)

1. Slack listener (`slack_on_new_message`): tag or manager reply -> POC Studio Agent -> thread reply; owner "approve" reply -> Approve gate; bot joined -> link rows by channel name.
2. Save POC from Slack (agent tool): creates the row, or notes the manager when the thread matches `bot_thread_ts`; results `created`, `needs_manager`, `exists`, `noted`. One automation instead of data-plan.md's two (Create POC from tag plus Note manager), to stay at 8.
3. Read channels into History (60 s schedule).
4. Start build (called by the Build button).
5. Receive build result (`callableApi`: PRD, final assets, gate feedback; posts to Slack; DMs the owner).
6. Approve gate (called by the Approve button and by the listener for the owner).
7. Suggest skill improvements (weekly schedule; Simple Call LLM node).
8. Approve skill suggestion (called by the Approve button on the Feedback page).

Agents: POC Studio Agent only (1 of 2). Pages: Home, POC page, Feedback (3 of 3). The one pending suggestion for the call comes from running automation 7 once in rehearsal on the seeds (PRD writer has 5 open tickets, Mockup drafter 2, so only PRD writer fires); no "Run now" button.

## Refusals (rule 3 and the "nothing beyond the beats" rule)

- A "Send back" form, a "Run now" skill button or a second scheduled caller: no. The request puts feedback in Claude and the run is periodic. Smaller option: the rehearsal run produces the one pending suggestion.
- A `rejected` suggestion status or a reject button, an `admin_email` field, a Skills admin page, a settings or roles page, a channel-map object, a seen-ts object, a second agent "Skill Coach", Slack interactive buttons, a Create POC modal, My queue, POC Pilot assistant (all in older source versions or the other storylines), right-aligned own-message bubbles: no, no beat or request line uses them.
- Reusing any existing Slack connection or the Orbit objects and API: no (slack.app, objects.reuse).
- Cutting the skill loop for the hearsay about last night's simplification: no (cut.skill-loop).
- Firing a real cloud run when Approve is clicked on a seeded row: no (build.continue_by guard).
